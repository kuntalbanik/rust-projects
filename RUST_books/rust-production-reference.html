01

Installation & Toolchain (rustup)

কনসেপ্ট — What it is

rustup হলো Rust-এর official installer ও version manager — এটা দিয়ে compiler (rustc), package manager (cargo), এবং একাধিক toolchain version ইনস্টল ও সুইচ করা যায়।

উদ্দেশ্য — Purpose

সিস্টেমে Rust ডেভেলপমেন্ট এনভায়রনমেন্ট সেটআপ ও ভার্সন ম্যানেজ করা।

কোথায় ব্যবহার — Where used

প্রতিটা Rust প্রোজেক্টের শুরুতে, CI/CD pipeline-এ নির্দিষ্ট toolchain version pin করায়।

🦀 Professional Note

rustup toolchain install stable/nightly দিয়ে একাধিক version রাখা যায় — প্রোডাকশনে সবসময় stable channel ব্যবহার করুন, nightly শুধু experimental feature টেস্ট করতে।rust-toolchain.toml ফাইলে version pin করে রাখলে পুরো টিম একই compiler version ব্যবহার করে, যা 'works on my machine' সমস্যা কমায়।

# ইনস্টল করা
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

# ভার্সন চেক ও আপডেট
rustc --version
rustup update stable
02

Cargo Basics

কনসেপ্ট — What it is

Cargo হলো Rust-এর build system ও package manager — dependency resolve, compile, test, এবং crate publish সবকিছুই এর মাধ্যমে হয়।

উদ্দেশ্য — Purpose

প্রোজেক্ট তৈরি, dependency ম্যানেজমেন্ট, বিল্ড ও রান করার একটা ইউনিফাইড ওয়ার্কফ্লো দেওয়া।

কোথায় ব্যবহার — Where used

প্রতিটা Rust প্রোজেক্টে — Cargo.toml দিয়ে metadata ও dependency, Cargo.lock দিয়ে exact version lock করা হয়।

🦀 Professional Note

Cargo.lock সবসময় version control-এ কমিট করুন (application-এর জন্য; library crate-এর জন্য সাধারণত না) — এটা নিশ্চিত করে সবাই একই dependency version পাচ্ছে, reproducible build দেয়। cargo check ব্যবহার করুন দ্রুত syntax/type error চেক করতে, পুরো build করার আগে — এটা অনেক দ্রুত।

cargo new my_project
cd my_project
cargo build          # ডিবাগ বিল্ড
cargo run            # কম্পাইল + রান
cargo check          # শুধু টাইপ-চেক, দ্রুত
cargo build --release # অপ্টিমাইজড প্রোডাকশন বিল্ড

Variables and Mutability

কনসেপ্ট — What it is

Rust-এ let দিয়ে ভ্যারিয়েবল ডিফল্টভাবে immutable — পরিবর্তনযোগ্য করতে হলে let mut লিখতে হয়। const দিয়ে compile-time constant ডিফাইন করা হয়।

উদ্দেশ্য — Purpose

ডিফল্টভাবে immutability enforce করে accidental mutation থেকে সৃষ্ট বাগ প্রতিরোধ করা।

কোথায় ব্যবহার — Where used

প্রায় প্রতিটা লাইনে — কিন্তু বিশেষভাবে shared state, concurrent কোডে immutability-ই মূল safety guarantee।

🦀 Professional Note

Immutability Rust-এর সবচেয়ে গুরুত্বপূর্ণ design decision — 'অপ্রয়োজনে mut লিখবেন না' এটাই idiomatic। Shadowing (একই নামে let দিয়ে নতুন ভ্যারিয়েবল বানানো) mut থেকে আলাদা — shadowing টাইপ বদলাতে পারে, mut পারে না।

fn main() {
    let x = 5;
    // x = 6; // কম্পাইল এরর: cannot assign twice to immutable variable
    let mut y = 5;
    y = 6; // ঠিক আছে
    const MAX_POINTS: u32 = 100_000;
    let x = x + 1; // shadowing, নতুন বাইন্ডিং
    println!("{y} {x} {MAX_POINTS}");
}

Data Types

কনসেপ্ট — What it is

Rust statically ও strongly typed — scalar type (integer, float, bool, char) এবং compound type (tuple, array) built-in আছে। Integer overflow ডিবাগ বিল্ডে panic করে, রিলিজ বিল্ডে wrap করে।

উদ্দেশ্য — Purpose

মেমরির সঠিক আকার ও আচরণ অনুযায়ী ডেটা সংরক্ষণ করা, compile-time এই টাইপ ভুল ধরে ফেলা।

কোথায় ব্যবহার — Where used

প্রতিটা variable declaration, function signature, struct field-এ।

🦀 Professional Note

i32 ডিফল্ট integer টাইপ (বেশিরভাগ ক্ষেত্রে যথেষ্ট ফাস্ট), usize array/vector index-এর জন্য ব্যবহার হয়। Debug বিল্ডে overflow panic করলেও রিলিজ বিল্ডে silently wrap করে — সেফটি-ক্রিটিক্যাল কোডে checked_add/checked_sub ব্যবহার করা উচিত।

fn main() {
    let i: i32 = -5;
    let u: u64 = 100;
    let f: f64 = 3.14;
    let b: bool = true;
    let c: char = 'র';
    let tup: (i32, f64, bool) = (500, 6.4, true);
    let arr: [i32; 3] = [1, 2, 3];
    println!("{i} {u} {f} {b} {c} {:?} {:?}", tup, arr);
}

Functions

কনসেপ্ট — What it is

fn কীওয়ার্ড দিয়ে function ডিফাইন করা হয়; প্যারামিটার টাইপ অবশ্যই explicit লিখতে হয়, রিটার্ন টাইপ -> দিয়ে। শেষ expression (সেমিকোলন ছাড়া) স্বয়ংক্রিয়ভাবে রিটার্ন হয়।

উদ্দেশ্য — Purpose

কোড reuse ও modular ডিজাইন করা।

কোথায় ব্যবহার — Where used

প্রতিটা প্রোগ্রামের core building block, main() হলো এন্ট্রি পয়েন্ট।

🦀 Professional Note

Statement আর expression-এর পার্থক্য Rust-এ গুরুত্বপূর্ণ — শেষ লাইনে সেমিকোলন থাকলে সেটা () (unit type) রিটার্ন করবে, ভুলে সেমিকোলন দিয়ে দেওয়া একটা কমন বিগিনার বাগ ('expected type, found ()')।

fn add(a: i32, b: i32) -> i32 {
    a + b // কোনো সেমিকোলন নেই, এটাই রিটার্ন ভ্যালু
}
fn main() {
    println!("{}", add(3, 4));
}

Comments

কনসেপ্ট — What it is

// দিয়ে single-line, /* */ দিয়ে multi-line কমেন্ট। /// দিয়ে item-এর ঠিক উপরে doc-comment লিখলে সেটা দিয়ে rustdoc স্বয়ংক্রিয় ডকুমেন্টেশন জেনারেট করে, এমনকি Markdown ও code example সাপোর্ট করে।

উদ্দেশ্য — Purpose

কোডের উদ্দেশ্য ব্যাখ্যা করা এবং auto-generated, testable ডকুমেন্টেশন তৈরি করা।

কোথায় ব্যবহার — Where used

Public API, library crate-এর প্রতিটা exported item-এ।

🦀 Professional Note

Doc-comment-এর ভেতরের code example cargo test দিয়ে সত্যিই compile ও run হয় ('doctest') — এটা নিশ্চিত করে ডকুমেন্টেশন কখনো বাস্তব কোডের সাথে out-of-sync হয় না, যা অন্য ভাষায় সাধারণত হয়ে যায়।

/// দুইটা সংখ্যা যোগ করে।
///
/// # Examples
/// ```
/// assert_eq!(my_crate::add(2, 3), 5);

Control Flow

কনসেপ্ট — What it is

if একটা expression (ভ্যালু রিটার্ন করতে পারে), loop/while/for তিন ধরনের লুপ আছে। loop-কে break দিয়ে ভ্যালুসহ রিটার্ন করানো যায়, labeled loop দিয়ে nested loop control করা যায়।

উদ্দেশ্য — Purpose

শর্তসাপেক্ষ branching ও repetition করা।

কোথায় ব্যবহার — Where used

প্রায় সব লজিকে — validation, iteration, retry logic।

🦀 Professional Note

if let value = condition {} else {} স্টাইলে if থেকে সরাসরি ভ্যালু assign করা যায় (let x = if cond { 5 } else { 6 };) — এটা Rust-কে অনেক expression-oriented করে তোলে। for loop iterator নিয়ে কাজ করে, তাই index-based লুপের চেয়ে for item in collection বেশি idiomatic ও নিরাপদ (out-of-bounds সম্ভাবনা নেই)।

fn main() {
    let x = if 5 > 3 { "বড়" } else { "ছোট" };
    let mut counter = 0;
    let result = loop {
        counter += 1;
        if counter == 10 { break counter * 2; }
    };
    for elem in [10, 20, 30] { println!("{elem}"); }
    println!("{x} {result}");
}

Ownership & Memory

08

Ownership

কনসেপ্ট — What it is

Rust-এর সবচেয়ে মূল concept — প্রতিটা ভ্যালুর একটা মাত্র owner থাকে, owner scope থেকে বেরিয়ে গেলে ভ্যালু automatically drop (deallocate) হয়ে যায়। Assignment বা function-এ পাস করলে (non-Copy টাইপে) ownership move হয়ে যায়, আগের ভ্যারিয়েবল আর ব্যবহারযোগ্য থাকে না।

উদ্দেশ্য — Purpose

Garbage collector ছাড়াই compile-time এ memory safety guarantee করা — no dangling pointer, no double-free, no memory leak (সাধারণ ক্ষেত্রে)।

কোথায় ব্যবহার — Where used

প্রতিটা Rust প্রোগ্রামে — এটা এড়ানো যায় না, পুরো ভাষা এই মডেলের উপর দাঁড়িয়ে।

🦀 Professional Note

এটাই Rust শেখার সবচেয়ে কঠিন কিন্তু সবচেয়ে মূল্যবান অংশ — 'borrow checker-এর সাথে যুদ্ধ' নতুনদের জন্য common experience, কিন্তু একবার mental model তৈরি হয়ে গেলে এটা runtime crash-এর বদলে compile-time এ বাগ ধরে ফেলে, যা production-এ অমূল্য।

fn main() {
    let s1 = String::from("hello");
    let s2 = s1; // s1-এর ownership s2-তে move হলো
    // println!("{s1}"); // কম্পাইল এরর: value borrowed after move
    println!("{s2}");

    let n1 = 5;
    let n2 = n1; // i32 হলো Copy টাইপ, তাই এটা কপি হয়, move না
    println!("{n1} {n2}"); // দুটোই valid
} // s2 এখানে drop হয়, মেমরি ফ্রি হয়

References and Borrowing

কনসেপ্ট — What it is

& দিয়ে একটা ভ্যালুর reference (borrow) নেওয়া যায় — ownership নেওয়া ছাড়াই ভ্যালু access করা যায়। একই সময়ে হয় একাধিক immutable reference (&T), অথবা একটামাত্র mutable reference (&mut T) থাকতে পারে, দুটো একসাথে না।

উদ্দেশ্য — Purpose

Ownership move না করেই function-এর মধ্যে ভ্যালু পাস করা, এবং compile-time এ data race প্রতিরোধ করা।

কোথায় ব্যবহার — Where used

Function parameter, struct field access, collection iteration-এ।

🦀 Professional Note

এই 'borrowing rule' (একটা mutable XOR একাধিক immutable) কম্পাইলার এনফোর্স করে — এটাই Rust-কে data race-free করে তোলে multi-threaded কোডেও, কোনো runtime lock ছাড়াই। rustc-এর error message গুলো borrow checker সমস্যা বোঝাতে খুবই helpful, ধৈর্য ধরে পড়ুন।

fn calculate_length(s: &String) -> usize { s.len() }
fn change(s: &mut String) { s.push_str(", world"); }
fn main() {
    let s1 = String::from("hello");
    let len = calculate_length(&s1); // borrow, ownership move হয়নি
    println!("{s1} has length {len}");

    let mut s2 = String::from("hello");
    change(&mut s2);
    println!("{s2}");
}

The Slice Type

কনসেপ্ট — What it is

Slice (&[T] বা &str) একটা collection-এর contiguous অংশের reference — ownership ছাড়াই। এটাও একটা ধরনের borrow, তাই ownership rule মেনে চলে।

উদ্দেশ্য — Purpose

পুরো collection কপি না করে তার একটা অংশ নিরাপদে reference করা।

কোথায় ব্যবহার — Where used

String-এর substring নেওয়া, array/vector-এর একটা অংশ function-এ পাঠানো।

🦀 Professional Note

Function parameter-এ &String না নিয়ে &str নেওয়া বেশি idiomatic (deref coercion-এর মাধ্যমে &String এমনিতেই &str-এ কাজ করে) — এটা function-কে বেশি flexible/generic বানায়, String literal এবং owned String দুটোই accept করতে পারে।

fn first_word(s: &str) -> &str {
    let bytes = s.as_bytes();
    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' { return &s[0..i]; }
    }
    &s[..]
}
fn main() {
    let s = String::from("hello world");
    println!("{}", first_word(&s));
    let arr = [1, 2, 3, 4, 5];
    let slice = &arr[1..3];
    println!("{:?}", slice);
}

Structs

কনসেপ্ট — What it is

struct দিয়ে related field-কে একটা নামযুক্ত টাইপে গ্রুপ করা হয়। তিন ধরনের struct আছে: named-field, tuple struct, ও unit-like struct।

উদ্দেশ্য — Purpose

সম্পর্কিত ডেটাকে একটা logical, টাইপ-সেফ ইউনিটে সংগঠিত করা।

কোথায় ব্যবহার — Where used

Domain model (User, Order), config struct, API payload-এ।

🦀 Professional Note

Struct instantiate করার সময় field shorthand (Point { x, y } যখন ভ্যারিয়েবলের নাম field-এর সাথে মেলে) এবং struct update syntax (..other_instance) কোড অনেক সংক্ষিপ্ত করে। Debug ডিরাইভ (#[derive(Debug)]) না দিলে struct প্রিন্ট করা যায় না — নতুনদের কমন ভুল।

#[derive(Debug)]
struct User {
    username: String,
    active: bool,
}
fn main() {
    let username = String::from("karim");
    let user1 = User { username, active: true };
    let user2 = User { active: false, ..user1 };
    println!("{:?}", user2);
}

Methods

কনসেপ্ট — What it is

impl ব্লকের ভেতরে struct/enum-এর সাথে method সংজুক্ত করা হয়। প্রথম parameter &self, &mut self, বা self হয় — কোন ধরনের access দরকার তা নির্দিষ্ট করে। impl ব্লকে self ছাড়া function হলো associated function (যেমন Type::new())।

উদ্দেশ্য — Purpose

একটা টাইপের সাথে behavior সংযুক্ত করে object-oriented-এর মতো API দেওয়া।

কোথায় ব্যবহার — Where used

Constructor প্যাটার্ন (::new()), domain logic, builder প্যাটার্নে।

🦀 Professional Note

&self নাকি &mut self নাকি self নেওয়া হবে সেটা ঠিক করা একটা গুরুত্বপূর্ণ API design সিদ্ধান্ত — self (ownership নেওয়া) method সাধারণত builder প্যাটার্নে ব্যবহৃত হয় (fn build(self) -> Product), যাতে ব্যবহারের পর আর ব্যবহার করা না যায়।

struct Rectangle { width: u32, height: u32 }
impl Rectangle {
    fn new(width: u32, height: u32) -> Self { Self { width, height } }
    fn area(&self) -> u32 { self.width * self.height }
}
fn main() {
    let rect = Rectangle::new(30, 50);
    println!("area: {}", rect.area());
}

Enums

কনসেপ্ট — What it is

enum দিয়ে এমন একটা টাইপ ডিফাইন করা হয় যার ভ্যালু নির্দিষ্ট কয়েকটা variant-এর যেকোনো একটা হতে পারে — প্রতিটা variant চাইলে ভিন্ন ভিন্ন ডেটাও বহন করতে পারে (Java/C-এর enum থেকে অনেক বেশি শক্তিশালী)।

উদ্দেশ্য — Purpose

সীমিত সংখ্যক সম্ভাব্য state/variant, প্রতিটার সাথে সম্পর্কিত ডেটাসহ, টাইপ-সেফভাবে represent করা।

কোথায় ব্যবহার — Where used

State machine, Option/Result-এর মতো core টাইপ, message/event টাইপ।

🦀 Professional Note

Rust-এর Option<T> এবং Result<T, E> — দুটোই আসলে built-in enum, এবং এরাই null-pointer ও exception ছাড়া error/absence হ্যান্ডেল করার মূল হাতিয়ার। match-এর সাথে combine করলে কম্পাইলার নিশ্চিত করে সব variant হ্যান্ডেল হয়েছে (exhaustiveness check) — এটা production কোডে বাগ কমানোর একটা বড় কারণ।

enum Shape {
    Circle(f64),
    Rectangle(f64, f64),
    Triangle { base: f64, height: f64 },
}
fn area(s: &Shape) -> f64 {
    match s {
        Shape::Circle(r) => std::f64::consts::PI * r * r,
        Shape::Rectangle(w, h) => w * h,
        Shape::Triangle { base, height } => 0.5 * base * height,
    }
}
fn main() { println!("{}", area(&Shape::Circle(2.0))); }

Pattern Matching (match)

কনসেপ্ট — What it is

match একটা এক্সপ্রেশনকে একাধিক pattern-এর বিপরীতে চেক করে, প্রথম যেটা মিলবে সেই ব্রাঞ্চ execute হবে। কম্পাইলার জোর করে সব সম্ভাব্য case (exhaustive) কভার করাতে বাধ্য করে, বা _ দিয়ে বাকি সব ধরতে হয়।

উদ্দেশ্য — Purpose

Enum/ডেটার structure অনুযায়ী নিরাপদ, exhaustive branching করা।

কোথায় ব্যবহার — Where used

Enum handling, Result/Option unwrap করা, complex conditional logic-এ।

🦀 Professional Note

match-এর exhaustiveness check প্রোডাকশন কোডে একটা বড় সুরক্ষা — enum-এ নতুন variant যোগ করলে সব জায়গার match ব্লক কম্পাইল-টাইমে error দেখাবে যেখানে সেই variant হ্যান্ডেল হয়নি, ফলে কোনো case ভুলে বাদ পড়ে না।

fn describe(n: i32) -> &'static str {
    match n {
        0 => "শূন্য",
        1..=9 => "এক অঙ্কের",
        n if n < 0 => "ঋণাত্মক",
        _ => "বড় সংখ্যা",
    }
}
fn main() { println!("{}", describe(5)); }

if let / let-else

কনসেপ্ট — What it is

if let একটা single-pattern match-কে সংক্ষিপ্ত করে যখন শুধু একটা variant নিয়েই আগ্রহ থাকে, বাকিদের নিয়ে না। let...else pattern না মিললে early return/break/panic করতে বাধ্য করে।

উদ্দেশ্য — Purpose

সব variant হ্যান্ডেল না করে শুধু প্রাসঙ্গিক একটা case নিয়ে সংক্ষিপ্তভাবে কাজ করা।

কোথায় ব্যবহার — Where used

Option/Result থেকে একটা নির্দিষ্ট ভ্যালু বের করা, config-এর optional field হ্যান্ডেল করায়।

🦀 Professional Note

পুরো match ব্লক লেখা যখন অপ্রয়োজনীয় বয়লারপ্লেট মনে হয়, তখন if let/let-else বেছে নিন — কিন্তু যদি সব variant নিয়ে চিন্তা করা জরুরি হয়, তাহলে match-এর exhaustiveness safety হারাবেন না।

fn main() {
    let config_max: Option<u8> = Some(3);
    if let Some(max) = config_max {
        println!("সর্বোচ্চ: {max}");
    }

    let Some(x) = config_max else {
        panic!("কনফিগ নেই!");
    };
    println!("x = {x}");
}

🦀 Professional Note

entry(key).or_insert(default) প্যাটার্ন Rust-এ counting/grouping লজিকের idiomatic উপায় — Java/Go-এর মতো ম্যানুয়ালি exists-চেক করে insert করার দরকার হয় না। ডিফল্টভাবে HashMap-এর হ্যাশ ফাংশন DoS-resistant কিন্তু তুলনামূলক ধীর — পারফরম্যান্স-ক্রিটিক্যাল কোডে FxHashMap-এর মতো বিকল্প বিবেচনা করা যায়।

use std::collections::HashMap;
fn main() {
    let text = "hello world hello rust";
    let mut counts: HashMap<&str, i32> = HashMap::new();
    for word in text.split_whitespace() {
        *counts.entry(word).or_insert(0) += 1;
    }
    println!("{:?}", counts);
}

panic! (Unrecoverable Errors)

কনসেপ্ট — What it is

panic! macro কল হলে প্রোগ্রাম error message প্রিন্ট করে stack unwind করে (বা abort করে) বন্ধ হয়ে যায় — এটা 'এই অবস্থা থেকে চলা সম্ভব না' বোঝায়।

উদ্দেশ্য — Purpose

Programmer bug বা truly unrecoverable অবস্থা signal করা, যেখানে চালিয়ে যাওয়া নিরাপদ না।

কোথায় ব্যবহার — Where used

Invariant violation, prototype/test কোড, array out-of-bounds-এর মতো internal bug ধরায়।

🦀 Professional Note

Library কোডে unwrap()/expect() ব্যবহার minimize করুন — এগুলো panic ট্রিগার করে, যা library ব্যবহারকারীর প্রোগ্রাম ক্র্যাশ করাতে পারে। Production application কোডেও panic কে normal error flow-এর জন্য ব্যবহার করবেন না, শুধু genuinely unrecoverable bug-এর জন্য রাখুন।

fn main() {
    let v = vec![1, 2, 3];
    // v[99]; // panic: index out of bounds
    let x: Option<i32> = None;
    // x.unwrap(); // panic: called `Option::unwrap()` on a `None` value
    let x2: Option<i32> = None;
    x2.expect("এখানে একটা ভ্যালু থাকা উচিত ছিল"); // কাস্টম panic message
}

Result (Recoverable Errors)

কনসেপ্ট — What it is

Result<T, E> একটা enum যার দুটো variant: Ok(T) সাফল্য, Err(E) ব্যর্থতা। এটাই Rust-এ exception-এর বিকল্প — error explicit ভাবে টাইপ সিস্টেমে দেখা যায়, ignore করা কঠিন।

উদ্দেশ্য — Purpose

এমন অপারেশনের ফলাফল টাইপ-সেফভাবে ফেরত দেওয়া যা ব্যর্থ হতে পারে, caller-কে explicit ভাবে হ্যান্ডেল করতে বাধ্য করা।

কোথায় ব্যবহার — Where used

File I/O, network call, parsing — প্রায় সব fallible অপারেশনে।

🦀 Professional Note

? অপারেটর দিয়ে error propagate করা (fn foo() -> Result<T, E> { let x = risky()?; ... }) বয়লারপ্লেট অনেক কমায় — এটা Rust-এর সবচেয়ে ব্যবহৃত idiom-গুলোর একটা। unused Result কম্পাইলার warning দেয় (#[must_use]), তাই accidentally error ignore করা কঠিন — এটা Go-এর তুলনায় বড় সেফটি সুবিধা।

use std::fs::File;
use std::io::{self, Read};

fn read_username() -> Result<String, io::Error> {
    let mut f = File::open("user.txt")?; // ? দিয়ে error propagate
    let mut s = String::new();
    f.read_to_string(&mut s)?;
    Ok(s)
}
fn main() {
    match read_username() {
        Ok(name) => println!("নাম: {name}"),
        Err(e) => println!("এরর: {e}"),
    }
}

To panic! or Not to panic! (Strategy)

কনসেপ্ট — What it is

কখন panic! ব্যবহার করা উচিত আর কখন Result রিটার্ন করা উচিত তা নিয়ে নির্দেশিকা — সাধারণ নিয়ম: library কোডে caller-কে সিদ্ধান্ত নিতে দিন (Result), যেখানে failure genuinely unexpected/impossible সেখানে panic গ্রহণযোগ্য।

উদ্দেশ্য — Purpose

সঠিক error-handling strategy বেছে নেওয়া, যাতে API predictable ও ব্যবহারযোগ্য থাকে।

কোথায় ব্যবহার — Where used

Library API ডিজাইন, prototype vs production কোড decision-এ।

🦀 Professional Note

Prototype/example/test কোডে unwrap() ঠিক আছে, কিন্তু production library-তে সেটা caller-এর হাতে ছেড়ে দেওয়াই ভালো (Result রিটার্ন করে)। যেখানে টাইপ সিস্টেম দিয়েই invalid state prevent করা সম্ভব (যেমন custom validated টাইপ বানিয়ে), সেটা runtime panic/error check-এর চেয়ে ভালো ডিজাইন।

// Library কোড: caller-কে সিদ্ধান্ত নিতে দিন
pub fn parse_config(s: &str) -> Result<Config, ConfigError> { /* ... */ Ok(Config{}) }

Generic Types

কনসেপ্ট — What it is

<T> সিনট্যাক্স দিয়ে function, struct, enum-কে টাইপ-প্যারামিটারাইজড করা যায় — একই কোড একাধিক কংক্রিট টাইপে reuse হয়, কম্পাইল-টাইমে monomorphization হয়ে প্রতিটা টাইপের জন্য আলাদা optimized কোড তৈরি হয়।

উদ্দেশ্য — Purpose

কোড duplication এড়িয়ে টাইপ-সেফ, reusable কোড লেখা, কোনো runtime overhead ছাড়াই।

কোথায় ব্যবহার — Where used

Generic data structure (Stack<T>, Container<T>), utility function-এ।

🦀 Professional Note

Rust generics 'zero-cost abstraction' — monomorphization-এর কারণে generic কোড ঠিক ততটাই দ্রুত যতটা হাতে-লেখা টাইপ-নির্দিষ্ট কোড, কোনো runtime dispatch overhead নেই (dyn Trait ব্যবহার না করলে)। কিন্তু compile time ও বাইনারি সাইজ বাড়তে পারে বেশি monomorphization হলে।

fn largest<T: PartialOrd>(list: &[T]) -> &T {
    let mut largest = &list[0];
    for item in list {
        if item > largest { largest = item; }
    }
    largest
}
fn main() {
    println!("{}", largest(&[10, 25, 3, 47]));
}

Traits

কনসেপ্ট — What it is

উদ্দেশ্য — Purpose

একাধিক টাইপের জন্য common behavior/contract define করা, polymorphism অর্জন করা।

কোথায় ব্যবহার — Where used

Custom trait ডিজাইন, standard trait implement করা (Display, Debug, Clone, Iterator ইত্যাদি), trait bound দিয়ে generic function constrain করা।

🦀 Professional Note

trait bound-এ impl Trait সিনট্যাক্স (fn notify(item: &impl Summary)) static dispatch দেয় (compile-time, দ্রুত), আর dyn Trait dynamic dispatch দেয় (runtime, একই collection-এ ভিন্ন ভিন্ন কংক্রিট টাইপ রাখতে দেয় কিন্তু সামান্য overhead সহ) — কোনটা দরকার বুঝে বেছে নিন।

trait Summary {
    fn summarize(&self) -> String {
        String::from("(পড়ুন আরো...)")
    }
}
struct Article { title: String }
impl Summary for Article {
    fn summarize(&self) -> String { format!("শিরোনাম: {}", self.title) }
}
fn notify(item: &impl Summary) { println!("খবর! {}", item.summarize()); }
fn main() { notify(&Article { title: String::from("Rust ১.০ রিলিজ") }); }

Lifetimes

কনসেপ্ট — What it is

Lifetime annotation ('a) কম্পাইলারকে বলে দেয় একাধিক reference-এর মধ্যে বৈধতার সময়কাল কেমন সম্পর্কযুক্ত — এটা runtime এ কিছু করে না, শুধু compile-time এ dangling reference প্রতিরোধ করে।

উদ্দেশ্য — Purpose

নিশ্চিত করা কোনো reference তার data-এর বাইরে বেঁচে না থাকে (dangling reference prevent করা) — কোনো garbage collector বা runtime check ছাড়াই।

কোথায় ব্যবহার — Where used

Function যেখানে একাধিক reference parameter নেয় ও reference রিটার্ন করে, struct যেখানে reference field আছে।

🦀 Professional Note

বেশিরভাগ ক্ষেত্রে lifetime elision rule-এর কারণে explicit annotation লিখতে হয় না — কম্পাইলার নিজেই অনুমান করতে পারে। যখন কম্পাইলার নিজে বুঝতে পারে না (একাধিক reference input, reference রিটার্ন), তখনই explicit 'a annotation দরকার হয়। এটা নতুনদের কাছে সবচেয়ে বিমূর্ত concept, কিন্তু এটা memory safety-র মূল স্তম্ভ garbage collector ছাড়াই।

fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
fn main() {
    let s1 = String::from("অনেক লম্বা একটা স্ট্রিং");
    let s2 = String::from("ছোট");
    println!("{}", longest(s1.as_str(), s2.as_str()));
}

কনসেপ্ট — What it is

উদ্দেশ্য — Purpose

বয়লারপ্লেট trait implementation কম্পাইলারকে দিয়ে জেনারেট করানো, কোড সংক্ষিপ্ত রাখা।

কোথায় ব্যবহার — Where used

প্রায় প্রতিটা custom struct/enum-এ — Debug প্রিন্টিং, Clone কপি করার জন্য, PartialEq তুলনার জন্য।

🦀 Professional Note

#[derive(Debug)] প্রায় সব struct-এ যোগ করা ভালো অভ্যাস — এটা debugging/logging-কে অনেক সহজ করে দেয়। Copy trait শুধু stack-only ডেটার জন্য derive করা যায় (যেমন সব field যদি Copy হয়) — heap ডেটাসহ struct-এ Copy derive করার চেষ্টা করলে কম্পাইল এরর হবে।

struct Point { x: i32, y: i32 }
fn main() {

    let p2 = p1.clone();

}

Closures

কনসেপ্ট — What it is

Closure হলো anonymous function যা তার environment থেকে ভ্যারিয়েবল ক্যাপচার করতে পারে — Fn, FnMut, FnOnce তিন ধরনের trait দিয়ে closure কীভাবে ক্যাপচার করছে (borrow, mutable borrow, বা move/consume) তা নির্ধারিত হয়।

উদ্দেশ্য — Purpose

State ক্যাপচার করে ছোট, ইনলাইন function হিসেবে লজিক পাস করা।

কোথায় ব্যবহার — Where used

Iterator adapter (.map, .filter), callback, event handler-এ।

🦀 Professional Note

move কীওয়ার্ড দিয়ে closure-কে জোর করে ownership নিতে বাধ্য করা যায় (থ্রেড spawn করার সময় প্রায়ই দরকার হয়, কারণ থ্রেড closure-এর lifetime মূল স্কোপের চেয়ে বেশি হতে পারে)। কম্পাইলার automatically সবচেয়ে কম-restrictive trait (Fn > FnMut > FnOnce) ব্যবহার করার চেষ্টা করে, যেভাবে closure ভ্যারিয়েবল ব্যবহার করছে তার উপর ভিত্তি করে।

fn main() {
    let x = vec![1, 2, 3];
    let equal_to_x = move |z: Vec<i32>| z == x; // move করে ownership নিলো
    let y = vec![1, 2, 3];
    println!("{}", equal_to_x(y));

    let mut count = 0;
    let mut increment = || { count += 1; println!("count: {count}"); };
    increment(); increment();
}

Iterators

কনসেপ্ট — What it is

Iterator trait নিয়ে lazy, chainable sequence processing — .map(), .filter(), .collect() ইত্যাদি adapter দিয়ে পাইপলাইন বানানো যায়। lazy মানে iterator শুধু .collect()/.sum() এর মতো consuming method কল হলেই আসলে execute হয়।

উদ্দেশ্য — Purpose

Collection-এর উপর declarative, composable transformation করা — ম্যানুয়াল loop লেখার বদলে।

কোথায় ব্যবহার — Where used

Data transformation pipeline, filtering, aggregation, functional-স্টাইল ডেটা প্রসেসিং-এ।

🦀 Professional Note

Iterator adapter zero-cost abstraction — কম্পাইল হয়ে সাধারণত হাতে-লেখা loop-এর সমান বা কখনো কখনো দ্রুততর কোডে পরিণত হয় (compiler bound-check elide করতে পারে)। প্রথমে ম্যানুয়াল for loop-এর তুলনায় ধীর মনে হলেও, ভুল ধারণা — Rust-এর iterator অন্য ভাষার lazy sequence থেকে অনেক বেশি অপ্টিমাইজড।

fn main() {
    let v = vec![1, 2, 3, 4, 5];
    let sum: i32 = v.iter().filter(|&&x| x % 2 == 0).map(|x| x * x).sum();
    println!("{sum}");
    let names: Vec<String> = v.iter().map(|n| format!("num-{n}")).collect();
    println!("{:?}", names);
}

Loops vs. Iterators (Performance)

কনসেপ্ট — What it is

হাতে-লেখা index-based for loop আর iterator adapter chain (.map/.filter) — দুটোই কম্পাইল হয়ে প্রায় একই assembly-তে পরিণত হয়, কারণ Rust compiler iterator abstraction-কে অপ্টিমাইজ করে দেয় (zero-cost abstraction)।

উদ্দেশ্য — Purpose

Idiomatic, readable কোড লিখেও পারফরম্যান্স বিসর্জন দিতে না হওয়া নিশ্চিত করা।

কোথায় ব্যবহার — Where used

Performance-sensitive কোড লেখার সময় কোন স্টাইল বেছে নেবেন তা নিয়ে সিদ্ধান্ত নেওয়ায়।

🦀 Professional Note

সন্দেহ থাকলে iterator স্টাইল বেছে নিন — এটা সাধারণত বেশি readable, কম bug-prone (ম্যানুয়াল index handling নেই, out-of-bounds সম্ভাবনা নেই), এবং পারফরম্যান্স একই বা ভালো। শুধু profiling data দেখে সিদ্ধান্ত নিন কোনো নির্দিষ্ট hot-path optimize করার দরকার আছে কিনা।

fn main() {
    let buffer = vec![1.0f64; 1000];
    // ম্যানুয়াল loop
    let mut sum1 = 0.0;
    for i in 0..buffer.len() { sum1 += buffer[i]; }
    // Iterator adapter — একই পারফরম্যান্স
    let sum2: f64 = buffer.iter().sum();
    println!("{sum1} {sum2}");
}

Writing Tests

কনসেপ্ট — What it is

#[test] অ্যাট্রিবিউট দেওয়া function গুলো cargo test দিয়ে চলে; assert!, assert_eq!, assert_ne! ম্যাক্রো দিয়ে expectation যাচাই করা হয়।

Box<T>

কনসেপ্ট — What it is

Box<T> সবচেয়ে সহজ smart pointer — heap-এ ডেটা রাখে, ownership একটাই, compile-time size known না থাকা টাইপ (recursive টাইপ) বা বড় ডেটা move না করে ব্যবহারের জন্য দরকার হয়।

উদ্দেশ্য — Purpose

Heap-এ ডেটা রাখা, recursive টাইপ সম্ভব করা, বড় ডেটা copy না করে move করা।

কোথায় ব্যবহার — Where used

Recursive data structure (linked list, tree), trait object (Box<dyn Trait>), বড় struct efficiently move করায়।

🦀 Professional Note

Recursive enum ছাড়া Box<T> খুব কম প্রয়োজন হয় — বেশিরভাগ ক্ষেত্রে stack allocation যথেষ্ট এবং দ্রুততর। Box<dyn Trait> ব্যবহার করা হয় যখন runtime এ ভিন্ন কংক্রিট টাইপের ভ্যালু একই collection-এ রাখতে হয় (heterogeneous collection)।

enum List {
    Cons(i32, Box<List>),
    Nil,
}
use List::{Cons, Nil};
fn main() {
    let list = Cons(1, Box::new(Cons(2, Box::new(Cons(3, Box::new(Nil))))));
}

Deref Trait

কনসেপ্ট — What it is

Deref trait implement করলে একটা কাস্টম টাইপকে * অপারেটর দিয়ে dereference করা যায়, এবং deref coercion স্বয়ংক্রিয়ভাবে &MyBox<T> কে &T-তে কনভার্ট করে দেয় function call-এ।

উদ্দেশ্য — Purpose

Smart pointer-কে সাধারণ reference-এর মতো transparent ভাবে ব্যবহার করার সুযোগ দেওয়া।

কোথায় ব্যবহার — Where used

কাস্টম smart pointer টাইপ তৈরি করায়, standard library-এর Box/Rc-এর behavior বোঝায়।

🦀 Professional Note

Deref coercion-এর কারণে &String, &Box<String> সবই সরাসরি &str প্রত্যাশা করা function-এ পাস করা যায় — এই স্বচ্ছতা Rust API ব্যবহার করাকে অনেক সহজ করে, কিন্তু নিজে custom smart pointer বানানো ছাড়া সাধারণত এটা নিজে implement করার দরকার হয় না।

use std::ops::Deref;
struct MyBox<T>(T);
impl<T> Deref for MyBox<T> {
    type Target = T;
    fn deref(&self) -> &T { &self.0 }
}
fn hello(name: &str) { println!("হ্যালো, {name}!"); }
fn main() {
    let m = MyBox(String::from("Rust"));
    hello(&m); // deref coercion: &MyBox<String> -> &String -> &str
}

Drop Trait

কনসেপ্ট — What it is

Drop trait implement করলে কোনো ভ্যালু scope থেকে বের হওয়ার ঠিক আগে (owner drop হওয়ার সময়) কাস্টম cleanup কোড চালানো যায় — এটা automatic, ম্যানুয়ালি কল করার দরকার হয় না (বরং drop() সরাসরি কল করা নিষিদ্ধ, std::mem::drop() ব্যবহার করতে হয়)।

উদ্দেশ্য — Purpose

Resource (file handle, network connection, lock) স্বয়ংক্রিয়ভাবে, নির্ভরযোগ্যভাবে release করা — RAII প্যাটার্ন।

কোথায় ব্যবহার — Where used

Custom resource management, connection pool, lock guard-এর মতো টাইপে।

🦀 Professional Note

Rust-এর ownership মডেলের সাথে Drop combine হয়ে RAII (Resource Acquisition Is Initialization) দেয় — এটা C++-এর মতোই কিন্তু কম্পাইলার-এনফোর্সড, তাই manual close()/cleanup ভুলে যাওয়ার বাগ প্রায় দূর হয়ে যায় production কোডে।

struct Connection { name: String }
impl Drop for Connection {
    fn drop(&mut self) { println!("{} বন্ধ হচ্ছে", self.name); }
}
fn main() {
    let _c = Connection { name: String::from("db-conn") };
    println!("কাজ চলছে...");
} // scope শেষ হলে স্বয়ংক্রিয়ভাবে drop() কল হবে

Rc<T> — Reference Counted Pointer

কনসেপ্ট — What it is

Rc<T> একই ডেটার multiple owner রাখার সুযোগ দেয় — একটা reference count রাখে, .clone() করলে count বাড়ে, প্রতিটা owner drop হলে count কমে, count শূন্য হলে ডেটা deallocate হয়। শুধু single-threaded ব্যবহারের জন্য।

উদ্দেশ্য — Purpose

একই ডেটা একাধিক জায়গা থেকে ownership শেয়ার করা যেখানে একটা single owner যথেষ্ট না।

কোথায় ব্যবহার — Where used

Graph/tree structure যেখানে একটা নোডের একাধিক parent থাকতে পারে, shared configuration data-তে।

🦀 Professional Note

Rc শুধু single-threaded — multi-threaded shared ownership দরকার হলে Arc<T> (Atomic Rc) ব্যবহার করতে হবে। Rc<T> শুধু immutable shared access দেয়; ভেতরের ডেটা পরিবর্তন করতে হলে RefCell<T>-এর সাথে কম্বাইন করতে হয় (Rc<RefCell<T>>)।

use std::rc::Rc;
fn main() {
    let a = Rc::new(String::from("shared data"));
    let b = Rc::clone(&a); // count বাড়লো, ডেটা কপি হলো না
    println!("count: {}", Rc::strong_count(&a));
    println!("{a} {b}");
}

RefCell<T> & Interior Mutability

কনসেপ্ট — What it is

RefCell<T> 'interior mutability' প্যাটার্ন দেয় — borrow checking কম্পাইল-টাইমের বদলে runtime এ enforce করা হয়, ফলে একটা immutable reference-এর ভেতরেও ডেটা মিউটেট করা যায় (কিন্তু rule ভাঙলে runtime panic হয়)।

উদ্দেশ্য — Purpose

এমন পরিস্থিতিতে mutation দরকার যেখানে কম্পাইলার স্ট্যাটিকভাবে borrow rule যাচাই করতে পারে না, কিন্তু developer জানে এটা নিরাপদ।

কোথায় ব্যবহার — Where used

Mock object টেস্টিং, Rc<RefCell<T>> দিয়ে shared mutable state, self-referential-এর মতো জটিল স্ট্রাকচারে।

🦀 Professional Note

RefCell compile-time safety-কে runtime check-এ রূপান্তর করে — ভুল হলে (একাধিক mutable borrow) প্রোগ্রাম panic করবে, compile error না। তাই এটা 'শেষ অস্ত্র' হিসেবে ব্যবহার করা উচিত, যখন সাধারণ &mut দিয়ে ডিজাইন করা সম্ভব না — অতিরিক্ত ব্যবহার করলে Rust-এর মূল safety guarantee (compile-time check) দুর্বল হয়ে যায়।

use std::cell::RefCell;
fn main() {
    let data = RefCell::new(5);
    *data.borrow_mut() += 10;
    println!("{}", data.borrow());
}

Reference Cycles & Memory Leaks

কনসেপ্ট — What it is

Rc<T> দিয়ে দুটো ভ্যালু একে অপরকে reference করলে (cycle) reference count কখনো শূন্যে নামে না, ফলে মেমরি কখনো free হয় না — এটাই Rust-এ (যদিও rare) মেমরি লিকের প্রধান উপায়। Weak<T> দিয়ে এই সমস্যা এড়ানো যায় (non-owning reference, count বাড়ায় না)।

উদ্দেশ্য — Purpose

Reference cycle এড়িয়ে সত্যিকারের memory leak প্রতিরোধ করা, বিশেষত parent-child-এর মতো bidirectional structure-এ।

কোথায় ব্যবহার — Where used

Tree structure-এ parent pointer (child->parent), observer প্যাটার্ন-এ।

🦀 Professional Note

সাধারণ নিয়ম: parent-থেকে-child সম্পর্কে Rc<T> (owning) ব্যবহার করুন, child-থেকে-parent সম্পর্কে Weak<T> (non-owning) ব্যবহার করুন — এভাবে cycle তৈরিই হয় না। এটা Rust-এর একটা known trade-off: memory safety guarantee করে (no use-after-free), কিন্তু logical memory leak পুরোপুরি প্রতিরোধ করে না, developer-কেই সচেতন থাকতে হয়।

use std::rc::{Rc, Weak};
use std::cell::RefCell;
struct Node {
    value: i32,
    parent: RefCell<Weak<Node>>, // non-owning, cycle এড়ায়
    children: RefCell<Vec<Rc<Node>>>,
}

Threads

কনসেপ্ট — What it is

std::thread::spawn() দিয়ে একটা নতুন OS thread তৈরি করা হয় যা concurrently চলে। JoinHandle.join() দিয়ে thread শেষ হওয়ার জন্য অপেক্ষা করা হয়।

উদ্দেশ্য — Purpose

একাধিক কাজ সত্যিকারের parallel-এ (multi-core ব্যবহার করে) চালানো।

কোথায় ব্যবহার — Where used

CPU-bound parallel কম্পিউটেশন, background processing, একাধিক independent task।

🦀 Professional Note

'Fearless Concurrency' Rust-এর একটা প্রধান selling point — ownership ও borrowing rule কম্পাইল-টাইমেই data race প্রতিরোধ করে, যা C++/অন্যান্য ভাষায় শুধু runtime tool (thread sanitizer) দিয়ে ধরা পড়ে। main thread শেষ হয়ে গেলে spawn করা thread গুলো join() না করা থাকলে জোর করে বন্ধ হয়ে যায় — গুরুত্বপূর্ণ কাজে সবসময় join() করুন।

use std::thread;
fn main() {
    let handle = thread::spawn(|| {
        for i in 1..5 { println!("thread থেকে: {i}"); }
    });
    for i in 1..3 { println!("main থেকে: {i}"); }
    handle.join().unwrap();
}

Message Passing (Channels)

কনসেপ্ট — What it is

std::sync::mpsc (multiple producer, single consumer) দিয়ে থ্রেডের মধ্যে channel-ভিত্তিক communication করা হয় — 'shared memory-র বদলে message পাঠিয়ে communicate করা' এই দর্শন।

উদ্দেশ্য — Purpose

থ্রেডের মধ্যে shared mutable state ছাড়াই নিরাপদে ডেটা transfer করা।

কোথায় ব্যবহার — Where used

Producer-consumer pattern, worker thread থেকে result সংগ্রহ করায়।

🦀 Professional Note

send() করার পর সেই ভ্যালুর ownership channel-এর মাধ্যমে move হয়ে যায় — sender thread এরপর সেই ভ্যালু আর ব্যবহার করতে পারে না, কম্পাইলার এটা এনফোর্স করে, ফলে accidental shared-mutable-access সম্ভবই না।

use std::sync::mpsc;
use std::thread;
fn main() {
    let (tx, rx) = mpsc::channel();
    thread::spawn(move || {
        tx.send(String::from("hello from thread")).unwrap();
    });
    let received = rx.recv().unwrap();
    println!("{received}");
}

Shared-State Concurrency (Mutex/Arc)

কনসেপ্ট — What it is

Mutex<T> একবারে একটা থ্রেডকে ডেটা access করতে দেয় (.lock() দিয়ে); Arc<T> (Atomic Rc) থ্রেড-সেফভাবে একই ডেটা একাধিক থ্রেডের মধ্যে shared ownership দেয়। একসাথে Arc<Mutex<T>> খুবই কমন combination।

উদ্দেশ্য — Purpose

একাধিক থ্রেড থেকে একই shared mutable state নিরাপদে access/modify করা।

কোথায় ব্যবহার — Where used

Shared counter, cache, connection pool-এর মতো state-এ multi-threaded অ্যাক্সেস দরকার হলে।

🦀 Professional Note

Mutex<T>.lock() একটা Result রিটার্ন করে (poisoned lock detect করতে, যখন কোনো থ্রেড lock ধরে রেখে panic করে) — production কোডে .unwrap() না করে গ্রেসফুলি হ্যান্ডেল করার কথা ভাবুন। কম্পাইলার নিশ্চিত করে Mutex ছাড়া raw shared mutable state কম্পাইলই হবে না — data race কম্পাইল-টাইম এররে ধরা পড়ে, runtime bug হিসেবে না।

use std::sync::{Arc, Mutex};
use std::thread;
fn main() {
    let counter = Arc::new(Mutex::new(0));
    let mut handles = vec![];
    for _ in 0..10 {
        let counter = Arc::clone(&counter);
        handles.push(thread::spawn(move || {
            let mut num = counter.lock().unwrap();
            *num += 1;
        }));
    }
    for h in handles { h.join().unwrap(); }
    println!("Result: {}", *counter.lock().unwrap());
}

Send and Sync Traits

কনসেপ্ট — What it is

Send মার্কার trait বোঝায় একটা টাইপ থ্রেডের মধ্যে নিরাপদে transfer (ownership move) করা যায়; Sync বোঝায় একটা টাইপ একাধিক থ্রেড থেকে একই সময়ে reference করা নিরাপদ। প্রায় সব টাইপ automatically এগুলো পায়, কম্পাইলার নিজে থেকেই যাচাই করে।

উদ্দেশ্য — Purpose

কম্পাইল-টাইমে নিশ্চিত করা কোন টাইপ থ্রেডের মধ্যে নিরাপদে শেয়ার/পাঠানো যায়, কোনটা যায় না।

কোথায় ব্যবহার — Where used

Concurrency primitives ডিজাইন করার সময়, generic থ্রেড-সেফ কোড লেখায়।

🦀 Professional Note

সাধারণত এই trait নিয়ে সরাসরি কিছু লিখতে হয় না — কম্পাইলার automatically ডিরাইভ করে এবং enforce করে (যেমন Rc<T> Send/Sync না, তাই থ্রেডে পাঠানোর চেষ্টা করলে compile error দেবে, এটাই আপনাকে Arc<T> ব্যবহার করতে বাধ্য করবে)। এই দুটো trait-ই মূল কারণ কেন Rust-এর concurrency 'fearless' — ভুল টাইপ ভুল জায়গায় ব্যবহার করলে প্রোগ্রাম কম্পাইলই হয় না।

use std::rc::Rc;
use std::sync::Arc;
use std::thread;
fn main() {
    let data = Arc::new(5); // Arc: Send + Sync, থ্রেডে পাঠানো নিরাপদ
    let d = Arc::clone(&data);
    thread::spawn(move || println!("{d}")).join().unwrap();
    // let r = Rc::new(5);
    // thread::spawn(move || println!("{r}")); // কম্পাইল এরর: Rc<i32> Send না
}

Futures and the Async Syntax

কনসেপ্ট — What it is

উদ্দেশ্য — Purpose

async fn fetch_data() -> String {

async fn main() {

Applying Concurrency with Async

কনসেপ্ট — What it is

উদ্দেশ্য — Purpose

একাধিক async অপারেশন একসাথে (একটার পর একটা সিরিয়ালি না) চালিয়ে সময় বাঁচানো।

কোথায় ব্যবহার — Where used

async fn task2() -> i32 { 2 }

async fn main() {
    let (a, b) = tokio::join!(task1(), task2());

উদ্দেশ্য — Purpose

use futures::future::join_all;
async fn fetch(id: i32) -> i32 { id * 2 }
#[tokio::main]
async fn main() {

async fn main() {

Trait Objects (dyn Trait)

কনসেপ্ট — What it is

Box<dyn Trait> বা &dyn Trait দিয়ে dynamic dispatch করা হয় — একই collection-এ ভিন্ন ভিন্ন কংক্রিট টাইপ রাখা যায় যতক্ষণ তারা সবাই একই trait implement করে, খরচ হয় সামান্য runtime vtable lookup overhead।

উদ্দেশ্য — Purpose

Runtime এ ভিন্ন ভিন্ন টাইপের ভ্যালু একই ইন্টারফেসের মাধ্যমে uniform ভাবে হ্যান্ডেল করা — Go/Java-এর interface-এর সবচেয়ে কাছাকাছি Rust ফিচার।

কোথায় ব্যবহার — Where used

Plugin architecture, GUI widget system, heterogeneous collection (Vec<Box<dyn Draw>>) এ।

🦀 Professional Note

Generic (impl Trait/monomorphization, static dispatch) আর dyn Trait (dynamic dispatch) এর মধ্যে বেছে নেওয়া একটা গুরুত্বপূর্ণ ডিজাইন সিদ্ধান্ত — static dispatch দ্রুততর কিন্তু বাইনারি সাইজ বাড়ায় ও heterogeneous collection সাপোর্ট করে না, dynamic dispatch flexible কিন্তু সামান্য runtime cost আছে।

trait Draw { fn draw(&self); }
struct Button; struct Slider;
impl Draw for Button { fn draw(&self) { println!("বাটন আঁকা হলো"); } }
impl Draw for Slider { fn draw(&self) { println!("স্লাইডার আঁকা হলো"); } }
fn main() {
    let components: Vec<Box<dyn Draw>> = vec![Box::new(Button), Box::new(Slider)];
    for c in components.iter() { c.draw(); }
}

Object-Oriented Design Patterns

কনসেপ্ট — What it is

উদ্দেশ্য — Purpose

Object-oriented ভাষা থেকে পরিচিত ডিজাইন প্যাটার্ন গুলো Rust-এর ownership মডেলের সাথে খাপ খাইয়ে ব্যবহার করা।

কোথায় ব্যবহার — Where used

State machine ইমপ্লিমেন্টেশন, plugin/strategy-based architecture ডিজাইনে।

🦀 Professional Note

trait State { fn next(self: Box<Self>) -> Box<dyn State>; fn name(&self) -> &str; }
struct Draft; struct Published;
impl State for Draft {
    fn next(self: Box<Self>) -> Box<dyn State> { Box::new(Published) }
    fn name(&self) -> &str { "Draft" }
}
impl State for Published {
    fn next(self: Box<Self>) -> Box<dyn State> { self }
    fn name(&self) -> &str { "Published" }
}

Pattern Syntax (Advanced)

কনসেপ্ট — What it is

উদ্দেশ্য — Purpose

Struct/enum/tuple destructuring, complex match condition-এ।

🦀 Professional Note

Pattern-এর গভীর সিনট্যাক্স (nested destructuring, guard condition) জানা থাকলে অনেক ম্যানুয়াল if-else chain এক লাইনের match-এ পরিণত হয় — কোড অনেক বেশি concise ও এক্সপ্রেসিভ হয়ে যায়, কিন্তু অতিরিক্ত জটিল pattern readability কমাতে পারে, ভারসাম্য বজায় রাখুন।

struct Point { x: i32, y: i32 }
fn main() {
    let p = Point { x: 0, y: 7 };
    match p {
        Point { x: 0, y } => println!("y অক্ষে, y={y}"),
        Point { x, y: 0 } => println!("x অক্ষে, x={x}"),
        Point { x, y } => println!("({x}, {y})"),
    }
    let msg = 5;
    match msg {
        n @ 1..=5 => println!("রেঞ্জে পাওয়া গেলো: {n}"),
        _ => println!("রেঞ্জের বাইরে"),
    }
}

কনসেপ্ট — What it is

unsafe ব্লকের ভেতরে raw pointer dereference, unsafe function কল, mutable static variable access করার মতো কাজ করা যায় যা কম্পাইলার নিজে যাচাই করতে পারে না — programmer নিজে সেই guarantee-র দায়িত্ব নেন।

উদ্দেশ্য — Purpose

যেখানে কম্পাইলার নিরাপদতা প্রমাণ করতে পারে না কিন্তু developer জানে এটা আসলে নিরাপদ, সেখানে নিয়ন্ত্রিতভাবে সেই সীমাবদ্ধতা bypass করা।

কোথায় ব্যবহার — Where used

🦀 Professional Note

fn main() {
    let mut num = 5;
    let r1 = &num as *const i32;
    let r2 = &mut num as *mut i32;
    unsafe {
        println!("r1: {}", *r1);
        *r2 = 10;
    }
}

Macros

কনসেপ্ট — What it is

Declarative macro (macro_rules!) pattern-matching দিয়ে কোড জেনারেট করে; procedural macro (derive/attribute/function-like) আরও শক্তিশালী, কম্পাইল-টাইমে টোকেন স্ট্রিম ম্যানিপুলেট করে কোড জেনারেট করে (যেমন #[derive(...)])।

উদ্দেশ্য — Purpose

Compile-time কোড জেনারেশন করে বয়লারপ্লেট কমানো, নতুন সিনট্যাক্স-এর মতো ফিচার তৈরি করা যা সাধারণ function দিয়ে সম্ভব না।

কোথায় ব্যবহার — Where used

println!/vec!-এর মতো নিজস্ব declarative macro, #[derive(Serialize)]-এর মতো procedural macro (serde crate-এ ব্যাপক ব্যবহৃত)।

🦀 Professional Note

Macro শক্তিশালী কিন্তু debug করা কঠিন এবং কম্পাইল সময় বাড়ায় — সাধারণ function/generic দিয়ে সমাধান করা গেলে সেটাই আগে বিবেচনা করুন, macro শুধু তখনই লিখুন যখন সত্যিই compile-time কোড জেনারেশন ছাড়া উপায় নেই।

macro_rules! square {
    ($x:expr) => { $x * $x };
}
fn main() {
    println!("{}", square!(5)); // 25
}

Building a TCP/Web Server

কনসেপ্ট — What it is

std::net::TcpListener দিয়ে raw TCP কানেকশন গ্রহণ করা হয়; প্রতিটা কানেকশন থ্রেড পুল (thread pool) দিয়ে হ্যান্ডেল করলে একাধিক client একসাথে সার্ভ করা যায়, single-thread করলে একটার পর একটা সিরিয়ালি প্রসেস হয়।

উদ্দেশ্য — Purpose

কাঁচা নেটওয়ার্ক লেভেলে request গ্রহণ ও response পাঠানোর মেকানিজম বোঝা ও ইমপ্লিমেন্ট করা।

কোথায় ব্যবহার — Where used

Custom protocol সার্ভার, HTTP server নিজে থেকে বানানোর learning exercise-এ (production-এ সাধারণত axum/actix-web-এর মতো framework ব্যবহার হয়)।

🦀 Professional Note

নিজের হাতে thread pool বানানো একটা চমৎকার শেখার অভিজ্ঞেয় (channel + worker thread pattern), কিন্তু প্রোডাকশন ওয়েব সার্ভিসে axum বা actix-web-এর মতো battle-tested async framework ব্যবহার করা উচিত — এগুলো connection pooling, graceful shutdown, error handling অনেক বেশি robust ভাবে handle করে।

use std::net::{TcpListener, TcpStream};
use std::io::{Read, Write};

fn handle_connection(mut stream: TcpStream) {
    let mut buffer = [0; 512];
    stream.read(&mut buffer).unwrap();
    let response = "HTTP/1.1 200 OK\r\n\r\nHello!";
    stream.write_all(response.as_bytes()).unwrap();
}
fn main() {
    let listener = TcpListener::bind("127.0.0.1:7878").unwrap();
    for stream in listener.incoming() {
        handle_connection(stream.unwrap());
    }
}
